# WGDot v4.9.0: Yazi Custom Starter

This release makes personal Yazi Lua customization easier to discover and safer to maintain. It includes the merged changes from [PR #144](https://github.com/dillacorn/win-glaze-dots/pull/144).

## Install and update

- [Install](https://github.com/dillacorn/win-glaze-dots/blob/main/INSTALL.md)
- [Update](https://github.com/dillacorn/win-glaze-dots/blob/main/UPDATE.md)

## Yazi customization

- GitHub now includes a commented `UserProfile/AppData/Roaming/yazi/config/custom.lua` starter with a clearly marked place for personal settings.
- On first install or a successful managed apply with Yazi selected, WGDot creates `%APPDATA%\yazi\config\custom.lua` **only if missing**. Native and PowerShell fallback installers use no-clobber copying.
- `custom.lua` and personal `custom/*.lua` modules remain **user-owned**, outside the WGDot managed manifest. Normal updates and resets do not overwrite them.
- A single `custom.lua` entry point can explicitly load any number of additional Lua files in a chosen order using `dofile`; scripts are not automatically discovered or executed.
- Users overriding `YAZI_CONFIG_HOME` can create or copy their starter into that alternate directory.
- Full instructions: [YAZI_CUSTOMIZATION.md](https://github.com/dillacorn/win-glaze-dots/blob/main/YAZI_CUSTOMIZATION.md).
